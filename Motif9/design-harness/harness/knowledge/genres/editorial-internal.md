# Editorial & Internal Tools — Domain Intelligence

Internal tools are products with a captive audience; that is a reason to make them better, not worse.

## Users
Support, ops, finance, moderation, data teams, editors. Expert, high-frequency, multi-tab, keyboard-heavy. They measure the tool in seconds per task.

## Principles
- Seconds matter: command palette, shortcuts, bulk everything, remembered filters, no confirmation for reversible actions.
- The record is the hero: "what is it, what can I do, what happened" on one screen.
- Built on the product's tokens and components so it can become a product.
- Adaptive density: comfortable for training, compact for the floor.
- Auditability: who changed what, when, why — visible inline.

## Patterns
| Need | Pattern |
|---|---|
| Lookup | Global search with typed prefixes (user:, order:), recents |
| Record | Header (identity + status + actions), tabs (overview, activity, related), sticky actions |
| Queue | Table with SLA colour, claim/assign, next-in-queue shortcut |
| Bulk | Select → preview → dry-run → apply → report partial failures |
| Data entry | Long forms with sections and progress; autosave; validation inline |
| Dashboards | Few numbers, big; trend + comparison; drill-through, never static |

## Editorial specifics
Longform editor with real typography, revision history, comments, structured metadata sidebar, scheduling, multi-channel preview.

## Visual language
Quiet chrome, high-contrast data, status colours consistent with the product. Monospace for IDs and codes.

## HALT
Confirm dialog on reversible action · Unsaved loss · No keyboard path · Data hidden behind hover-only affordances.
